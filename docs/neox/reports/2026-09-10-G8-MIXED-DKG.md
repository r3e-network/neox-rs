## 4. 历史失败原因与修复根因

历史运行中 round 未推进的直接原因是旧 verifier library 与当前 ZK-v1 proving ceremony 不匹配：旧库对 84 条真实 calldata 全部返回 `0xa3a93fee (CommitmentInvalid())`，因此 `aggregatedCommitment` 为空。使用当前 ceremony 编译的 One/Two/Seven runtime 后，84/84 条 calldata 全部通过，最终 9 节点门禁完成 round 1→2。



1. **geth 验证者确实在参与**：node2–node7 各有 4 次 `DKG get transaction receipt successfully`（`method=share` / `method=reshare`）。
2. **reth 也在参与**：`Installed canonical Neo X DKG epoch shares` 共 **2991** 次；`Queued Neo X DKG validator tasks … inserted=2 round=2` ×263。
3. **reth 的 epoch 边界计算正确**：`Reset Neo X DKG tasks … height=3600 … round=2`，精确命中 `epochDuration=3600`。
4. **但轮次无法结算** —— 决定性证据：
   ```
   DKG reached targetHeight round=2 currentHeight=3600 aggregatedCommitment=   ← 空
   ```
   聚合承诺为空；随后 reth 记录 `Discarded unfinished Neo X DKG round outside its canonical window round=2`（全日志仅 1 次）。
5. 结果：链上 round 恒为 1。

**定性**：这是 **DKG 仪式未能产出聚合承诺**（参与/验证/聚合环节未达成 quorum），属**协议/创世配置层面**的问题，与 Rust↔Go 等价性无关。

### 已验证的关键环境事实

- **系统级 systemd unit 不能解决驻留问题**：即便取到 root（WSL 允许 `wsl.exe -u root` 免密）并建立 `/system.slice/g8-chain.service`，拓扑仍在启动它的会话退出后约 20s 被整体回收（VM 因 `vmIdleTimeout=-1` 存活）。**决定因素是「是否仍有会话附着」，不是进程归属。**
- **reth 日志的 ANSI 转义逐 token 插入**：`round<ESC>[0m<ESC>[2m=<ESC>[0m1`，故 `grep 'round=1 member=true'` 得 0 命中（假阴性）。所有计数均需先 `sed 's/\x1b\[[0-9;]*m//g'`。
