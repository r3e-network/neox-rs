## Release decision

RC6 is a prerelease candidate for independent Neo X full-node evaluation. The non-validator path
has passed the historical MainNet and TestNet replay/differential gates and a live unpinned
multi-thousand-block TestNet backfill. Validator mode remains explicitly experimental. This release
does not claim that every mixed-client DKG, prover, Anti-MEV, replacement, reorg, or validator fault
path is production-qualified.

## Candidate changes

- Route far-ahead Neo X block announcements through a bounded descendant-target scheduler so the
  Reth pipeline can stage headers and bodies before live dBFT follow.
- Fence managed DKG heartbeats, recovery persistence, owned transaction cleanup, and canonical-head
  release ordering across failures and reorgs.
- Bound Beacon inbound events by global count/bytes and per-peer required/droppable budgets, including
  a same-peer required-event reserve. The class partition intentionally permits up to eight queued
  events (and one maximum frame of bytes) in each class for one peer; the global 64-event/32 MiB
  bounds remain the aggregate DoS ceiling.
- Require an explicit `--validator.experimental` acknowledgement for public MainNet/TestNet
  validator startup.
- Isolate upstream Reth release workflows, publish Linux static prover assets only where supported,
  and build the advertised x86_64 artifact at the baseline CPU level.

## Security and qualification boundary

The internal Neo X review records 24 code findings as remediated in the candidate tree. The review
does not substitute for an independent protocol/security review. The following live validator gates
remain open: a full mixed Rust/Geth DKG epoch, prover delay/failure, transaction replacement,
encrypted transaction decryption/reconstruction, controlled reorg, and crash/view-change fault
injection.

`cargo audit --no-fetch` reports two lockfile advisories: `RUSTSEC-2026-0185` for `quinn-proto`
`0.11.14` and `RUSTSEC-2025-0055` for `tracing-subscriber` `0.2.25`. Neither package is reachable
from the current NeoX workspace target graph (`cargo tree --workspace --target all` prints no
inverse dependency for either); they remain lockfile-only release hygiene items and are not hidden
with advisory ignores. `cargo-deny 0.18.9` cannot complete on this lockfile because it crashes while
resolving Alloy feature metadata (`alloy-genesis@2.1.1`); this tooling limitation is recorded rather
than treated as a pass.

## Publication boundary

The release workflow must build from the exact annotated tag and create a prerelease draft. Before
publishing, verify the three platform bundles and checksums: Linux x86_64 and aarch64 must contain
`neox-rs`, `neox-dkg-migrate`, and `neox-dkg-prover`; macOS Apple Silicon must contain
`neox-rs` and `neox-dkg-migrate` only. The installer must resolve the tag and reject a checksum
mismatch. No stable `neox-v2.4.1` tag is created by this candidate.
